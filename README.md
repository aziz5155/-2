# العائلة الناجحة (Family Success)

تطبيق عائلي لتحفيز الأبناء عبر المهام، البرامج اليومية، النقاط، المكافآت،
الأهداف، الإنجازات، والتحديات — مبني ليكون أساسًا حقيقيًا قابلًا للنشر على
App Store وللتوسع تجاريًا، وليس نموذجًا تجريبيًا.

## البنية التقنية (Tech Stack)

| الطبقة | الاختيار | السبب |
|---|---|---|
| التطبيق | **React Native + Expo (Expo Router)**, TypeScript | أفضل مسار لتجربة iPhone ممتازة، تطوير سريع، ونشر حقيقي على App Store من نفس الكود |
| الخلفية (Backend) | **Supabase** (Postgres + Auth + Row Level Security + Realtime + Storage) | قاعدة بيانات علائقية حقيقية، مصادقة جاهزة (Apple/Google/Email)، وصلاحيات مفروضة من السيرفر (RLS) لا يمكن الالتفاف عليها من التطبيق — وهذا أساسي لتطبيق يخص بيانات أطفال |
| منطق الأعمال الحساس (نقاط، مكافآت، اعتماد مهام) | **دوال Postgres (SECURITY DEFINER RPC)** | كل عملية تمس النقاط تمر عبر دالة واحدة ذرية (atomic) بدل أن يعدّل التطبيق الأرصدة مباشرة — هذا ما يمنع الخصم المزدوج أو التلاعب |
| عمليات تتطلب صلاحيات عليا (إنشاء حساب الطفل، إعادة تعيين الرمز السري) | **Supabase Edge Functions** (Deno) | إنشاء مستخدم Auth آخر باسم الوالد لا يمكن أن يحدث من جهاز العميل مهما كانت الصلاحيات — يحتاج Service Role، لذلك وُضع في دوال سيرفرية معزولة |
| الحالة والبيانات في التطبيق | **@tanstack/react-query** (بيانات الخادم) + **zustand** (حالة محلية بسيطة: الثيم، اللغة، الجلسة) | فصل واضح بين "بيانات من الخادم" و"تفضيلات محلية"، مع تخزين مؤقت وحالات تحميل/خطأ جاهزة |
| التعدد اللغوي | **i18next / react-i18next**، عربي (RTL) افتراضي + إنجليزي (LTR) | دعم RTL كامل منذ اليوم الأول، وليس إضافة لاحقة |

## الحالة الحالية

هذا إصدار MVP حقيقي وليس عرضًا تجريبيًا: كل الشاشات تتحدث مع Supabase مباشرة
(لا بيانات وهمية Mock)، والصلاحيات مفروضة على مستوى قاعدة البيانات (RLS)، وكل
عملية نقاط تُسجَّل في سجل حركات (Ledger) دائم لا يُعدَّل ولا يُحذف.

### المطبَّق فعليًا

- تسجيل دخول ولي الأمر (بريد إلكتروني، Apple، وبنية جاهزة لـ Google) عبر Supabase Auth.
- إنشاء عائلة، إضافة أبناء بحساب PIN خاص بهم (بدون بريد إلكتروني)، دخول الطفل عبر "كود العائلة".
- المهام: إنشاء، تكرار (مرة واحدة/يومي/أسبوعي/أيام محددة/شهري)، أولوية، طريقة اعتماد (تلقائي/يدوي).
- البرامج: قوالب جاهزة (10 قوالب) + إنشاء برنامج مخصص + مكافأة إكمال البرنامج بالكامل.
- سجل النقاط (Points Ledger) الكامل: كل عملية بسبب واضح وتاريخ وطرف منفّذ.
- منح نقاط سريع / خصم نقاط (بسبب إلزامي) من لوحة ولي الأمر.
- متجر المكافآت: إنشاء مكافآت، طلب استبدال من الطفل، موافقة/رفض من الوالد، خصم آمن لا يتكرر.
- الأهداف (Goals) مع شريط تقدّم، وتفعّل تلقائيًا عند بلوغ الرصيد المطلوب.
- المستويات (5 مستويات) محسوبة من إجمالي النقاط التاريخية.
- الإنجازات (9 شارات) تُمنح تلقائيًا عبر تريغرز في قاعدة البيانات.
- الأيام المتتالية (Streak) برسائل تشجيعية دائمًا عند الانقطاع.
- التحديات العائلية (إنشاء، انضمام، مكافأة عند الإكمال).
- سجل نشاط العائلة (Activity Feed) وإشعارات داخل التطبيق (بنية جاهزة لـ Push مستقبلًا).
- الوضع الداكن/الفاتح/التلقائي، ودعم عربي RTL / إنجليزي LTR كامل.
- **تأكيد البريد الإلكتروني** برمز من 6 أرقام (إعادة إرسال بمهلة، رسائل عربية للأخطاء).
- **استعادة كلمة المرور** برابط آمن لمرة واحدة + تغييرها من داخل الحساب.
- **لوحة المالك** (`/(owner)`): إحصائيات حقيقية، إدارة العملاء وملفاتهم، الباقات
  والأسعار (يومي/أسبوعي/شهري/سنوي، قابلة للتعديل من الواجهة بالكامل)، أكواد
  الخصم (نسبة، تاريخ صلاحية، حد استخدام إجمالي/لكل عميل، أول N دفعة أو كل
  الدفعات)، سجل تدقيق تلقائي لكل تعديل، وإدارة فريق (مدير/دعم/تسويق/محاسبة)
  محصورة بالمالك.
- خطة مجانية حقيقية الاستخدام + نظام باقات وأكواد خصم يعمل فعليًا من طرف
  إلى طرف (بدون بوابة دفع فعلية بعد بطلب صريح — انظر أدناه).

### غير مكتمل عمدًا

راجع [`docs/EXTERNAL_SERVICES.md`](docs/EXTERNAL_SERVICES.md) للتفاصيل الكاملة، والأهم:

1. **مشروع Supabase فعلي** — يجب إنشاؤه من طرفك (مجاني، بدون بطاقة ائتمان).
2. **حساب Apple Developer** — مطلوب لتفعيل "Sign in with Apple" فعليًا وللنشر على App Store.
3. **بوابة دفع فعلية (Moyasar / Tap)** — مؤجَّلة بطلبك؛ نظام الباقات والأكواد
   يعمل بالكامل ويُسجِّل كل عملية بحالة "بانتظار بوابة الدفع" حتى تربط واحدة.
4. **Google OAuth Client ID** — لتفعيل "Continue with Google" فعليًا.
5. **Push Notifications الفعلية** — الجداول والبنية جاهزة، لكن الإرسال الفعلي يحتاج مشروع Expo/Apple Push مُهيّأ.
6. **المرحلتان 2 و3 من لوحة المالك**: الهدايا/التعويضات، الحملات، القواعد
   التلقائية، برنامج الإحالة، مكتبة القوالب الإدارية، تعديل محتوى الموقع،
   الإطلاق التدريجي للمزايا، مركز الدعم (بما فيه معاينة القراءة فقط)، ومساحة
   التجربة المعزولة — لم تُبنَ بعد، بالترتيب المتفق عليه معك.

## التشغيل محليًا

### 1. المتطلبات

- Node.js 20+
- تطبيق **Expo Go** على آيفون (للتجربة السريعة) أو Xcode لبناء Dev Client.

### 2. تثبيت الاعتماديات

```bash
npm install
```

### 3. إعداد Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com) (مجاني).
2. من **SQL Editor** في لوحة تحكم المشروع، شغّل ملفات `supabase/migrations/`
   **بالترتيب الرقمي** (0001 إلى 0009)، ثم `supabase/seed.sql`، ثم
   `supabase/seed_billing.sql`.
3. اتبع [`docs/OWNER_SETUP.md`](docs/OWNER_SETUP.md) لإنشاء حساب المالك
   (خطوتان: إضافة مستخدم من لوحة Supabase + تشغيل `supabase/owner_bootstrap.sql`).
4. من **Edge Functions**، انشر الدوال الثلاث في `supabase/functions/`:
   `create-child`, `child-login`, `reset-child-pin` (تحتاج Supabase CLI:
   `supabase functions deploy create-child` وهكذا لكل دالة).
5. من **Project Settings → API**، انسخ `Project URL` و `anon public key`.
6. اتبع قسم "1.1 رمز تأكيد البريد الإلكتروني" في
   [`docs/EXTERNAL_SERVICES.md`](docs/EXTERNAL_SERVICES.md) (تعديل قالب بريد
   واحد في لوحة Supabase، دقيقتان).

### 4. متغيرات البيئة

```bash
cp .env.example .env
# ثم املأ EXPO_PUBLIC_SUPABASE_URL و EXPO_PUBLIC_SUPABASE_ANON_KEY
```

### 5. التشغيل

```bash
npm run start   # يفتح Expo Dev Tools — امسح رمز QR بتطبيق Expo Go على آيفون
npm run ios     # يتطلب macOS + Xcode
```

### أوامر أخرى

```bash
npm run typecheck   # فحص TypeScript الكامل بدون بناء
npm run lint        # ESLint
npm test            # اختبارات الوحدة (المستويات، منطق تكرار المهام)
```

راجع أيضًا [`supabase/testing/README.md`](supabase/testing/README.md) لتشغيل
دورة عمل كاملة (عائلة → مهمة → نقاط → مكافأة) على قاعدة بيانات حقيقية محليًا،
دون الحاجة لمشروع Supabase.

## بنية المشروع

```
app/                    # الشاشات (Expo Router) — (auth) / (parent) / (child)
src/
  design-system/        # الثيم، الألوان، المكوّنات القابلة لإعادة الاستخدام
  i18n/                 # ترجمات عربي/إنجليزي
  lib/supabase.ts        # عميل Supabase + استدعاء Edge Functions
  services/              # طبقة منطق الأعمال — كل عملية Supabase تمر من هنا
  stores/                # حالة محلية (zustand): الجلسة، الثيم، اللغة
  providers/             # React Query Provider
  types/models.ts        # أنواع TypeScript لكل جداول قاعدة البيانات
  constants/levels.ts     # حساب المستويات من النقاط التاريخية
  utils/recurrence.ts     # منطق تكرار المهام (يومي/أسبوعي/أيام محددة/شهري)
supabase/
  migrations/            # SQL: الجداول، RLS، الدوال — تُشغَّل بالترتيب الرقمي
  functions/             # Edge Functions (Deno): عمليات تحتاج Service Role
  seed.sql               # القوالب الجاهزة + كتالوج الإنجازات
docs/                    # توثيق إضافي (معمارية، قاعدة البيانات، خدمات خارجية)
```

مزيد من التفاصيل: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) و
[`docs/DATABASE.md`](docs/DATABASE.md).

## الأمان والخصوصية (ملخص)

- **لا صلاحيات تُفرض من الواجهة فقط**: كل جدول محمي بـ Row Level Security على
  مستوى Postgres، وعمليات النقاط/الاعتماد/الاستبدال لا تُنفَّذ إلا عبر دوال
  SECURITY DEFINER تتحقق من الهوية والصلاحية بنفسها في كل استدعاء.
- **سجل نقاط دائم**: لا حذف ولا تعديل على `point_transactions` — أي تصحيح
  يكون بقيد جديد معاكس، فيبقى التاريخ كاملاً وقابلاً للتدقيق.
- **حساب الطفل معزول**: حساب حقيقي في نظام المصادقة (بريد داخلي غير معروض +
  رمز سري)، لا يمكنه رؤية بيانات عائلة أخرى ولا الوصول لإعدادات الوالد.
- **لا بيانات غير ضرورية**: لا نطلب من الطفل بريدًا إلكترونيًا أو رقم هاتف.
